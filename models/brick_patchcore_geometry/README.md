# Geometry-augmented brick PatchCore

This is the Anomalib Studio model used by the Mac live inspection tester.
It detects unmarked versus anomalous/marked brick faces. It does not distinguish
crosses from circles. CPU inference has been checked on macOS; this export has
not been validated on an Intel NPU or integrated with robot motion.

Download the weights from the
[GitHub Release](https://github.com/shashankdurgad/dlsj/releases/tag/brick-patchcore-geometry-v1).
Large binaries are release assets rather than files in Git history.

From the repository root, using GitHub CLI and Python 3.12 or newer:

```sh
gh release download brick-patchcore-geometry-v1 --repo shashankdurgad/dlsj \
  --pattern 'brick-patchcore-geometry-v1.tar.gz' --pattern SHA256SUMS --dir models/downloads
cd models/downloads
shasum -a 256 -c SHA256SUMS
tar -xzf brick-patchcore-geometry-v1.tar.gz
cd ../..
python3 -m venv .venv-inspect
.venv-inspect/bin/python -m pip install -r requirements-anomaly-live.txt
.venv-inspect/bin/python -m dlsj.inspect.live_web \
  --model-dir models/downloads/brick-patchcore-geometry-v1
```

Open http://localhost:8006, allow camera access, choose a camera and click Start
detection. Fit the complete brick face inside the movable inspection square.
Studio does not need to be running for `--model-dir`. For the existing Studio API
mode, use `--run-dir` instead, as documented in `docs/anomaly-live-camera.md`.

The archive contains `model.xml`, `model.bin`, the matching `studio_model.json`,
`evaluation.json`, `training_config.json`, and per-weight SHA-256 hashes in
`files.json`. It excludes captures, training images, compiled runtime caches and
the PyTorch checkpoint. Resize, ImageNet normalization and score postprocessing
are embedded in the export. The direct loader supplies RGB float32 NCHW [0,1]
images, matching Anomalib's OpenVINO inferencer.

## Training and calibration

- Model: PatchCore, pretrained WideResNet50-2, normal-only memory bank.
- Source: 69 normal captures × three frames = 207 original 320×320 images.
- Four geometric variants per image: safe rotation ±15°, padded scale/shift.
  1,035 normal images imported to Studio, which performs an internal split.
- CPU, seed 2026, one feature-extraction epoch, coreset sampling ratio 0.02.
- Selected among four candidates on real external validation only.
- Live decision: mean of three frame scores ≥ **0.9991861979166667** → anomalous.
  The score is not a probability. Studio's default threshold 0.5 is not the
  externally calibrated threshold used by this live tester.

| Held-out capture decision | Correct / total |
|---|---:|
| Accept unmarked | 15/16 |
| Detect cross as anomalous | 54/58 |
| Detect circle as anomalous | 50/55 |

These are anomaly decisions, not subtype classification accuracy. Capture groups
are separated, but physical brick/session identities were unavailable; only 16
normal test captures exist. Normalized scores often saturate at 1.0, which limits
calibration resolution. Validate lighting, framing and thresholds on the target
camera before relying on its decisions.

See `docs/anomaly-augmentation-and-supervision.md` for the experiment and the
separate exploratory supervised classifier. Training is orchestrated by
`scripts/train_augmentation_studio.py`; augmentations are generated by
`python -m dlsj.inspect.augment`.

To reproduce the Studio API extensions and Mac inference fixes, apply
`patches/anomalib-studio-437669f.patch` to an Anomalib Studio checkout at
`437669f437b0d552c7d8382316e49cbaff574ce8` using `git apply /path/to/patch`.
It adds training seeds and coreset ratios, Mac worker settings, RGB decoding,
and a separate compiled-model cache per model. This patch is for the sibling
Anomalib Studio repository, not the dlsj repository.
